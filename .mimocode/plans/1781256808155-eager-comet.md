# Flutter UI迁移计划 - 混合模式

## 项目现状分析

### 当前架构
- **12个Activity**: MainActivity, AiChatActivity, Settings系列, ExamActivity等
- **3个Fragment**: AiChatFragment, AgendaAiComposeBottomSheetFragment, AgendaAddEntrySelectorDialogFragment
- **24个布局文件**: XML布局，Material Design组件
- **数据层**: SharedPreferences + SQLite双存储，Manager类静态方法模式

### 关键依赖
- Material Design Components (MaterialCardView, BottomNavigationView等)
- Jsoup (网页抓取)
- OpenAI GPT3 Java Service
- Markwon (Markdown渲染)
- Splash Screen API

---

## 推荐方案：Platform Channel混合模式

### 方案概述
保留Android原生的业务逻辑层（数据存储、网络请求、AI调用），仅将UI层替换为Flutter。

### 优势
1. **渐进式迁移** - 可以逐页面替换，风险低
2. **复用现有逻辑** - 数据层代码无需重写
3. **学习曲线平缓** - 可以逐步掌握Flutter

## 迁移步骤

### 阶段1：环境准备 (1-2天)

#### 1.1 Flutter环境搭建
```bash
# 安装Flutter SDK
# 配置Android Studio插件
# 创建Flutter模块
flutter create --template module flutter_ui_module
```

#### 1.2 项目集成
在 `settings.gradle.kts` 中添加：
```kotlin
include(":flutter_ui_module")
```

在 `app/build.gradle.kts` 中添加依赖：
```kotlin
implementation(project(":flutter_ui_module"))
```

### 阶段2：基础架构 (2-3天)

#### 2.1 Platform Channel通信
创建 `MethodChannel` 实现Android与Flutter双向通信：

**Android侧** (`MainActivity.java`):
```java
// 在onCreate中初始化Flutter
FlutterEngine flutterEngine = new FlutterEngine(this);
flutterEngine.getDartExecutor().executeDartEntrypoint(
    DartEntrypoint.createDefault()
);

// 注册MethodChannel
MethodChannel channel = new MethodChannel(
    flutterEngine.getDartExecutor().getBinaryMessenger(),
    "cn.edu.hut.course/native"
);

channel.setMethodCallHandler((call, result) -> {
    if (call.method.equals("getCourses")) {
        // 调用现有CourseStorageManager
        List<Course> courses = CourseStorageManager.readCourses(this);
        result.success(serializeCourses(courses));
    }
    // ...其他方法
});
```

**Flutter侧**:
```dart
class NativeBridge {
  static const _channel = MethodChannel('cn.edu.hut.course/native');
  
  static Future<List<Course>> getCourses() async {
    final result = await _channel.invokeMethod('getCourses');
    return (result as List).map((e) => Course.fromMap(e)).toList();
  }
}
```

### 阶段3：UI页面迁移 (按优先级)

#### 3.1 首批迁移页面（推荐）

**优先级1：今日页面 (Today Page)**
- 复杂度：中等
- 动画机会：时间显示渐变、课程卡片滑动、周概览条形图动画
- 建议：用 `AnimatedContainer` + `Hero` 动画实现流畅过渡

**优先级2：个人中心 (Profile Page)**
- 复杂度：简单
- 动画机会：卡片展开/收起、列表项进入动画
- 建议：用 `ListView.builder` + `AnimatedList` 实现

**优先级3：设置页面**
- 复杂度：简单
- 动画机会：页面切换动画、开关切换动画
- 建议：用 `PageRouteBuilder` 自定义过渡动画

#### 3.2 暂不迁移的页面

**保留原生：**
- `AiChatFragment` - 依赖Markwon渲染Markdown，迁移成本高
- `CourseScraper` - 网页抓取逻辑，保持原生更稳定
- `BrowserActivity` - WebView相关，保持原生

## 风险与注意事项

### 潜在风险
1. **性能开销** - Flutter引擎增加APK大小约10-15MB
2. **内存占用** - 双引擎运行增加内存消耗
3. **调试复杂度** - Android/Flutter混合调试较复杂

### 应对策略
1. **渐进式迁移** - 先从简单页面开始
2. **性能监控** - 使用Flutter DevTools监控
3. **备份原生代码** - 保留原生实现作为回退方案
