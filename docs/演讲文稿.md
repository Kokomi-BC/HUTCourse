> **适用场景**：课程答辩 / 项目展示 / 竞赛路演  
> **建议时长**：5–8 分钟  
> **演讲风格**：产品演示 + 技术亮点结合

## 一、开场（约 30 秒）

各位老师、同学大家好。

今天我要介绍的项目叫做 **HUTCourse——湖南工大课程助理**。它是一款面向湖南工业大学学生的 **智能校园助手 Android 应用**。

简单来说，它做了一件事：**把课表、日程、导航、空教室查询这些校园里的高频操作，全部收进一个 App，而且你只需要「说一句话」就能搞定。**

---

## 二、为什么做这个项目？（约 1 分钟）

我们在校园生活中经常遇到这样的场景：

- 早上起来想查今天在哪上课，需要打开教务系统、登录、翻课表……至少五六步。
- 想找一间空教室上自习，不知道去哪查，更不知道哪些教室现在没人。
- 想去某栋教学楼，但作为新生根本不知道这栋楼在哪。

这些操作分散在不同的系统里——教务系统、课表截图、地图 App、备忘录……**信息碎片化，操作路径长**，每一天都在重复这些低效的操作。

而现有的课表类 App 大多只是**把课表搬到了手机上**，它们不会理解你的自然语言，不会帮你查空教室，不会告诉你教学楼在哪。

所以我们做了 **HUTCourse**——一个**以 AI 为核心、以课表为基础、覆盖校园全场景的智能助手**。

---

## 三、核心功能演示（约 3 分钟）

### 3.1 课表同步与展示

首先是核心功能——**课表**。

我们知道湖南工业大学使用的是**强智教务系统**，它没有开放 API，传统方式无法直接获取课表数据。我们的做法是：

> **Cookie 模拟登录 → HTTP 请求课表页面 → Jsoup HTML 解析 → 数据清洗去重 → 本地持久化**

我们同时抓取**常规课表**和**实验课表**两个数据源，自动合并去重，确保显示完整。

在前端，课表采用**周网格视图**展示，左侧是时间标尺，右侧周一至周日。每个课程以 **Material Design 3 卡片**形式呈现，显示课程名、教师、地点。当前正在上的课和选中的课会有主题色描边高亮。课程卡片支持点击查看详情、编辑信息、自定义颜色，甚至可以根据你的**当前位置显示教室距离提示**。

### 3.2 AI 智能对话

这就是我们这个项目最大的亮点——**AI 驱动的自然语言交互**。

传统的课表 App 需要你手动翻页、点击、查找。而在 HUTCourse 里，你只需要像跟人说话一样问：

> *"今天还有什么课？"*  
> *"下周三的高数在哪上？"*  
> *"帮我创建一个每周三下午四点在图书馆自习的日程。"*  
> *"明天上午 10 点到 11 点有空教室吗？"*

AI 会自动完成：**日期计算 → 周次匹配 → 数据查询 → 结果返回** 全链路。

它是怎么做到的？我们来看技术架构——

## 四、技术架构与创新点（约 2.5 分钟）

### 4.1 AI Agent 架构

我们采用的是 **LLM Agent（大模型智能体）架构**，基于 **ReAct（推理+行动）模式**。

当用户提问后，系统流程如下：

```
用户提问 → AiPromptCenter 构造提示词 → AiGateway 调用大模型
→ 模型返回文本（可能包含工具命令）
→ SkillCommandCenter 解析并执行命令（查询课表/创建日程/查空教室等）
→ 结果回传给模型 → 模型生成最终回答 → 展示给用户
```

这个**思考-行动-观察**的循环最多可以执行 30 轮，足以处理复杂的多步任务。

我们内置了 **6 大技能**，全部模块化设计：

| 技能 | 功能 |
|---|---|
| **CourseQuery** | 课表查询、课程检索 |
| **AgendaSkill** | 日程增删改查、重复规则 |
| **NavigationSkill** | 校园定位、楼栋导航 |
| **ClassroomSkill** | 空教室查询 |
| **NoteSkill** | 记忆读写 |
| **TavilySearchSkill** | 联网信息检索 |

这些技能通过 `SkillCommandCenter` 统一调度，支持**权限开关和黑白名单控制**，安全灵活。

### 4.2 课表抓取——突破无 API 限制

这是一个比较有技术难点的部分。强智教务系统没有开放接口，我们通过：

1. **WebView 模拟登录**，捕获 Cookie
2. 用 OkHttp 携带 Cookie 请求课表 HTML 页面
3. 使用 **Jsoup** 解析 HTML 表格结构
4. 分别解析**常规课表**和**实验课表**，去重合并
5. 内置**静默重试登录**机制，登录失效时自动引导重新登录

我们甚至还支持**备注课程**的解析，确保一些特殊安排的课程也不会遗漏。

### 4.3 课表网格渲染——纯代码动态构建

课表界面完全采用 **Java 代码动态构建**，没有使用 XML 布局。核心是 `GridLayout` 网格布局：**5 行 × 8 列**，第 0 列是时间标尺，第 1–7 列对应周一到周日。

渲染时经历三个阶段：

1. **数据准备**：遍历课程列表，根据当前周次筛选，转换为 `ScheduleCellEntry`，按「行号×列号」存入 HashMap
2. **智能合并**：同一门课跨多个节次时自动垂直合并；日程按时间范围跨格；多个条目冲突时水平分割或层叠显示
3. **卡片绘制**：每个课程生成 `MaterialCardView` 卡片，自适应字体、自动换行地点、根据背景亮度选择文字颜色

### 4.4 其他技术细节

- **数据层**：SharedPreferences 存课表 JSON + SQLite 持久化，双重保证
- **日程管理**：支持每天/每周/每月重复规则，短月跳过或月底策略
- **校园导航**：内置楼栋坐标与别名库，集成高德地图跳转
- **天气服务**：接入天元区天气数据
- **Markdown 渲染**：使用 Markwon 库，AI 回复支持富文本显示

### 4.5 关键技术栈

| 层面 | 技术 |
|---|---|
| 客户端 | Android (Java), Material Design 3, ViewPager2 |
| 构建 | Gradle, AGP 9.1.1, compileSdk 35 |
| 数据解析 | Jsoup (HTML), SQLite, SharedPreferences |
| 网络 | OkHttp, CookieManager |
| AI 接入 | AiGateway (SDK + HTTP 双模式) |
| 地图 | 高德地图 SDK |
| Markdown | Markwon 4.6.2 |

## 五、创新亮点总结（约 1 分钟）

总结一下，我们这个项目有 **4 个核心创新点**：

1. **突破教务系统无 API 限制**：通过 Cookie 模拟 + HTML 解析实现课表自动同步，双源抓取合并，技术方案可复用到其他高校
2. **AI 驱动的自然语言课表交互**：全国首创？——至少在湖南工业大学范围内，我们是第一个实现用自然语言直接对话课表的 App。不需要手动翻查，"一句话查课表"从愿景变成了现实
3. **校园场景化工具链**：将课表、日程、导航、空教室、天气、记忆整合为 AI 可调用的技能矩阵，形成"**查询—规划—导航—记录**"的闭环体验
4. **智能日程生成**：自然语言直接创建日程，AI 自动解析时间、地点、重复规则

### 可能的提问与回答

**Q：为什么选择 Java 而不是 Kotlin？**  
A：项目启动时团队成员对 Java 更熟悉，Java 在 Android 生态中成熟稳定，且与 AGP 9.x 兼容性良好。核心架构不依赖语言特性，后续可逐步迁移到 Kotlin。

**Q：AI 的响应速度如何？**  
A：取决于模型接口的响应时间。我们做了**流式输出**和**请求缓存**优化，并在网关层设置了合理的超时重试策略，大部分查询在 2–5 秒内可返回结果。

**Q：如果教务系统改版了怎么办？**  
A：课表抓取确实依赖 HTML 结构。我们的解析逻辑集中在 `CourseScraper` 一个类中，改版后只需调整该类中的选择器即可，维护成本可控。

**Q：与其他课表 App 相比最大的优势是什么？**  
A：其他课表 App 只解决了"看课表"这一个问题。HUTCourse 解决的是从"查课表"到"找教室"到"记日程"到"问 AI"的全链路需求，而且全部通过自然语言驱动。
